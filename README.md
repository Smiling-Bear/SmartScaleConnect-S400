用于在不同生态系统之间同步智能体脂秤数据的应用程序。

* 从以下平台/格式加载数据：[Garmin]、[Home Assistant]、[Mi Fitness]、[My TANITA]、[Picooc]、[Xiaomi Home]、[Zepp Life]、[CSV]、[JSON]


* 保存数据至以下平台/格式：[Garmin]、[Home Assistant]、[Zepp Life]、[CSV]、[JSON]


* 支持的参数：`Weight`（体重）、`BMI`、`Body Fat`（体脂率）、`Body Water`（水分）、`Bone Mass`（骨量）、`Metabolic Age`（代谢年龄）、`Muscle Mass`（肌肉量）、`Physique Rating`（体型评分）、`ProteinMass`（蛋白质）、`Visceral Fat`（内脏脂肪）、`Basal Metabolism`（基础代谢）、`Heart Rate`（心率）、`Skeletal Muscle Mass`（骨骼肌量）


* 支持多用户数据


* 支持脚本语言

## 配置说明

名为 `scaleconnect.yaml` 的配置文件可以存放在当前工作目录或应用程序二进制文件所在目录下。

[YAML](https://www.google.com/search?q=https://en.wikipedia.org/wiki/YAML) 格式对缩进和空格要求非常严格，请务必注意。

首次启动后，配置文件旁可能会生成 `scaleconnect.json` 文件。该文件包含服务认证所需的凭据信息。

配置文件示例：

```yaml
sync_alex_fitbit:
  from: fitbit AlexMyFitbitData.zip
  to: garmin alex@gmail.com garmin-password

sync_alex_zepp:
  from: zepp/xiaomi alex@gmail.com xiaomi-password
  to: garmin alex@gmail.com garmin-password
  expr:
    Weight: 'BodyFat == 0 || Date >= date("2024-11-25") ? 0 : Weight'

sync_alex_mifitness:
  from: mifitness alex@gmail.com xiaomi-password
  to: garmin alex@gmail.com garmin-password
  expr:
    Weight: 'BodyFat == 0 ? 0 : Weight'
    BodyFat: 'Date >= date("2025-04-01") && Source == "blt.3.1abcdefabcd00" ? 0 : BodyFat'

```

### 来源于/同步至：CSV

非常适合人类阅读的文本格式。文件内部的时间始终是你的本地时间。在 MS Office 中支持极佳，便于在其中构建快速分析图表。

你可以使用 [CSV] **文件**或 **HTTP 链接**作为数据源，并使用 CSV **文件**、**HTTP 链接**或 **标准输出 (stdout)** 作为数据目的地：

```yaml
sync_from_file:
  from: csv source.csv

sync_from_http:
  from: csv http://192.168.1.123/source.csv
  
sync_to_file:
  to: csv destination.csv

sync_to_http:
  to: csv http://192.168.1.123:8123/api/webhook/594b7e73-1f0f-4c3c-aded-eeaee78a6790

sync_to_stdout:
  to: csv stdout

```

从链接读取时将通过 GET 请求下载。输出到链接时将通过 POST 请求上传。

**Home Assistant 加载项**

你可以调用 `hassio.addon_stdin` 服务并将 **scaleconnect** 配置作为 `input` 参数传入。请记住，同步指令的名称位于配置的顶层，可以包含一个或多个此类指令。

```yaml
action: hassio.addon_stdin
data:

  input:
    sync_garmin:  # 同步名称（可自定义使用任意名称）
      from:
        Weight: '{{ states("sensor.mi_body_composition_scale_mass")|float }}'  # 可以使用模板

        BodyFat: 10.0
      to: garmin {username} {password}

```

```yaml
shell_command:

    /config/scaleconnect -c '{{ {
      "sync_garmin": {
        "from": {
          "Weight": states("sensor.mi_body_composition_scale_mass")|float,
        },
        "to": "garmin {username} {password}"
      }
    }|tojson }}'

```

### 同步至：Home Assistant

每次同步时，最新的称重数据都将上传至 Home Assistant。

你可以根据喜好自由修改示例，添加体脂秤的其他参数。数据将在 HA 重启期间继续保留，历史图表也将记录变化历史。

将以下内容添加到你的 **configuration.yaml**：

```yaml
input_number:
  alex_weight:
    name: Alex Weight
    min: 50
    max: 80
    unit_of_measurement: kg
    icon: mdi:weight
  alex_bmi:
    name: Alex BMI
    min: 15
    max: 30

```

添加自动化：

```yaml
alias: Weight Data
triggers:
  - trigger: webhook
    allowed_methods: [ POST ]
    local_only: true
    webhook_id: "594b7e73-1f0f-4c3c-aded-eeaee78a6790"  # 请修改为随机的 ID
conditions: []
actions:
  - action: persistent_notification.create
    data:
      message: "{{ trigger.json }}"  # 仅用于测试
  - action: input_number.set_value
    data:
      value: "{{ trigger.json.Weight|round(2) }}"
    target:
      entity_id: input_number.alex_weight  # 在此修改实体名称
  - action: input_number.set_value
    data:
      value: "{{ trigger.json.BMI|round(2) }}"
    target:
      entity_id: input_number.alex_bmi  # 在此修改实体名称
mode: single

```


## 命令行界面 (CLI)

**选项参数：**

* `-c {配置文件路径}` 或 `-c {YAML/JSON 格式的原始配置字符串}` - 配置文件路径或内容。


* `-r {持续时长}` - 超时后重复处理配置文件（格式：`2h0m0s`）。


* `-i` - “交互模式”，用于通过 `stdin` 接收 YAML/JSON 格式的配置文件内容（以 `\n` 结尾的单行字符串）。



**示例：** 从命令行发送配置内容并接收响应至 `stdout`：

```shell

```

通过在“交互模式”下运行应用程序，你可以通过 `stdin` 向其发送命令并在 `stdout` 中接收响应。

## 同步逻辑

每次启动应用程序时，体重数据都会进行全量同步：

* 加载整个时间段内的所有源数据。


* 加载整个时间段内的所有目标数据。


* 如果时间戳完全匹配，则认为数据相同。


* 如果所有其他参数完全匹配，则**跳过**该次称重。


* 如果其他参数不同，则该称重数据会被新数据**完全替换**。


* 如果 `Weight` 列的值为零，则目标位置处的称重数据**会被删除**。




* 如果时间戳不匹配，则该称重数据会**上传**到服务。


* 如果 `Weight` 列的值为零，则**跳过**该次称重。



首次启动时，建议将你所有服务中的数据全部下载到 CSV 文件中，并在 Excel 中进行分析，以排查异常数据。

如果你需要从 Garmin 中批量删除大量错误数据，可以将其下载到 CSV 文件中，将 `Weight` 列全部填为零，然后再次将此 CSV 文件上传到 Garmin。

## 脚本语言

你可以使用功能强大的脚本语言 —— [expr](https://expr-lang.org/) 来改变同步行为并修改称重数值。

```yaml
sync_expr:
  expr:
    Date: 'Date - duration("1h")'             # 字符串 RFC 3339 格式，你可以调整称重时间
    Weight: 'Weight > 60 ? 0 : Weight'        # 浮点数 kg，支持使用条件判断
    BMI: 'BMI * 0.95'                         # 浮点数指数，可以使用数学公式
    BodyFat: 'BodyFat - 5.0'                  # 浮点数百分比，可以使用数学公式
    BodyWater: 'BodyWater'                    # 浮点数百分比
    BoneMass: 'BoneMass'                      # 浮点数 kg
    MetabolicAge: 'MetabolicAge'              # 整数 岁
    MuscleMass: 'MuscleMass'                  # 浮点数 kg
    PhysiqueRating: 'PhysiqueRating'          # 整数 等级，范围 1 到 9
    ProteinMass: 'ProteinMass'                # 浮点数 kg
    VisceralFat: 'VisceralFat'                # 整数 等级，范围 1 到 59
    BasalMetabolism: 'BasalMetabolism'        # 整数 千卡
    BodyScore: 'BodyScore'                    # 整数 分数，范围 1 到 100
    HeartRate: 'HeartRate'                    # 整数 次/分
    Height: 'Height'                          # 浮点数 cm
    SkeletalMuscleMass: 'SkeletalMuscleMass'  # 浮点数 kg
    User: 'User'                              # 字符串
    Source: 'Source + " some other text"'     # 字符串，添加自定义文本信息

```

例如，许多体脂秤测量的是 `MuscleMass`（肌肉量）参数。但包括 Garmin 在内的专业体脂秤测量的是 `SkeletalMuscleMass`（骨骼肌量）。如果你希望在 Garmin 中显示 `MuscleMass` 参数来代替 `SkeletalMuscleMass`，可以这样做：

```yaml
sync_expr:
  expr:
    SkeletalMuscleMass: 'MuscleMass'  # 将骨骼肌量数据替换为普通肌肉量数据

```

例如，我买了一台新的小米体脂秤，不想再同步特定日期之后的 Zepp 数据。同时我也不想同步缺少体脂信息的测量数据（无效称重）：

```yaml
sync_alex_zepp:
  expr:
    Weight: 'BodyFat == 0 || Date >= date("2024-11-25") ? 0 : Weight'

```

又或者除了旧的 **小米 S400** 之外，我还买了一台新的 **小米八电极体脂秤**。现在 S400 显示的体脂率完全不准了，但我仍想保留旧秤的称重数据，因为它们包含 **骨骼肌量** 数据，而新秤没有这个参数。此外，我还想忽略没有体脂信息的称重。

```yaml
sync_alex_mifitness:
  expr:
    Weight: 'BodyFat == 0 ? 0 : Weight'  # 忽略没有体脂信息的称重
    BodyFat: 'Date >= date("2025-04-01") && Source == "blt.3.1abcdefabcd00" ? 0 : BodyFat'  # 将旧秤的体脂数据清零

```
